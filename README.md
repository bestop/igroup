# 邻里拼单 🏘️

面向小区邻居的微信拼单小程序：团长发起山姆等商超商品拼单 → 分享到微信群 → 邻居选份额加入 → **微信收款码扫码转账**或**提货时当面支付** → 团长确认收款、购买、通知提货。

> **资金原则**：小程序不触碰资金、不接入微信支付商户号。支付环节只做「记账 + 状态协同」，钱直接在邻居间通过个人收款码 / 现金 / 红包完成，小程序负责让每个人知道"该付多少、付没付、团长收没收"。

## 技术选型

- **微信小程序原生框架 + 微信云开发**（云数据库 + 云函数 + 云存储），无需自建服务器与域名
- 全部数据读写走**唯一云函数 `groupbuy`**（action 路由），不依赖数据库安全规则配置
- 金额一律用**整数分**计算，避免浮点误差
- 加入拼单使用**云函数事务 + 参与记录确定性 `_id`（拼单ID_openid）**，防超卖、防重复加入
- **定时触发器**（每 5 分钟）自动截单到期拼单
- 收款码图片存云存储，`<image show-menu-by-longpress>` 支持长按识别

## 快速开始

1. **导入项目**：微信开发者工具 → 导入 → 选择本目录；AppID 换成你自己的小程序 AppID（`project.config.json` 中目前是占位 `touristappid`）。云开发需要正式 AppID，测试号不支持。
2. **开通云开发**：工具栏「云开发」→ 开通并创建环境（按量付费免费额度即可跑）。
3. **部署云函数**：在编辑器中右键 `cloudfunctions/groupbuy` → 「上传并部署：云端安装依赖」。右键 `groupbuy` → 「上传触发器」，让每 5 分钟的自动截单定时器生效。
4. **环境 ID**（可选）：多环境时在 `miniprogram/app.js` 顶部 `CLOUD_ENV` 填入环境 ID；单环境可留空。
5. 编译运行。数据库集合（users / groupbuys / participants / notifications）**首次调用时自动创建**，无需手工建表。

### 订阅消息（可选，不做不影响主流程）

1. 小程序后台 → 功能 → 订阅消息 → 申请"一次性订阅"模板，拿到模板 ID。
2. 填入两处：
   - `miniprogram/utils/subscribe.js` 的 `SUBSCRIBE_TMPL_IDS`（用于引导用户授权）
   - `cloudfunctions/groupbuy/config.js` 的 `TEMPLATES`（payRemind / purchased / arrival / cancel 四类）
3. 模板字段按 `thing1`（拼单商品名）、`thing2`（状态说明）对齐，如你的模板字段不同，改 `buildSubData()` 即可。
4. 体验版调试时把 `MINI_STATE` 改为 `'trial'`。

## 核心流程与状态机

### 拼单维度

```
拼单中(open) ──截单(手动/定时)──> 已截单(closed) ──完成购买──> 待提货(purchased) ──完成──> 已完成(completed)
     └──────────────取消──────────────┴──────────────────────┘──> 已取消(cancelled)
```

### 支付维度（参与者）

```
待付款(unpaid)
  ├─ 微信收款码：扫码转账 → 点「我已付款」→ 待确认(paid_pending)
  │                                   ├─ 团长确认收款 ──────> 已确认(confirmed)
  │                                   └─ 团长标记未收到款 ──> 退回待付款(unpaid)
  └─ 当面支付：选择「提货时当面支付」(cash_on_pickup) ──团长「当面已收款」──> 已确认(confirmed)
```

## 关键设计说明

| 主题 | 说明 |
|---|---|
| 分摊计算 | 每份单价 = 整包价格 ÷ 每包拆分数量（四舍五入到分，整包取整的尾差由团长吸收）；快递/包装费再按总份数均摊（`fee_bearer=split` 时生效）。 |
| 团长自留 | 发起时填写"自留份数"，计入已拼份数、不生成收款记录；名单与收款管理中显示"团长自留"行，收款汇总只统计邻居应付。 |
| 编辑拼单 | 团长在「拼单中」可整单编辑（团长管理页进入，复用发起页表单）；保存后自动按新单价/费用重算所有参与记录的应付金额（支付状态不变）；已截单不可编辑。 |
| 移除参与者 | 仅「拼单中」可移除；事务内删除参与记录并回减已拼份数，份额立即释放可再被拼；已付款邻居移除时弹窗提示线下退款。 |
| 防超卖 | `joinGroupBuy` 在事务内重读拼单、校验剩余份数、写入参与记录并 `sold_shares` 自增；参与记录 `_id = 拼单ID_openid`，一人一单天然唯一。 |
| 截单检查 | `closeGroupBuy` 不带 `force` 时只返回未付款统计（N 人未确认付款、其中 M 人当面支付），团长弹窗确认后仍可截单——提示但不强制阻断。 |
| 提醒付款 | 对 unpaid 记录可「提醒付款」，`notifications` 表按 24 小时去重（每人每日限一次）。 |
| 提货收尾 | 参与者「确认提货」后若全员提完，拼单自动转已完成；对 unpaid 参与者团长可在提货阶段直接「当面已收款」转为已确认。 |
| 隐私 | 拼单详情页对非发起人隐藏各家的付款状态；收款明细仅团长管理页可见。 |
| 取消退款 | 取消拼单只做通知与状态留痕，"已付款请联系发起人退款"由参与端横幅提示，线下处理。 |

## 验收对照

- ✅ 发起拼单按「整包价格 + 每包拆分数量（+ 总包数）」录入，自动生成每份单价；团长可自留份数，剩余份数供拼单；快递费/包装费开关 + 承担方式，分摊实时预览
- ✅ 分享卡片「山姆瑞士卷拼单｜¥29.90/份｜剩3份」，点击直达详情；支持复制拼单信息
- ✅ 事务防超卖，份额步进器上限为剩余份数，金额实时计算
- ✅ 截单（手动提前 + 到点自动）后无法再加入；团长一键完成购买并通知全部参与者
- ✅ 收款码上传云存储、收款说明、长按识别 + 保存相册；「我已付款」→ 待确认
- ✅ 团长单笔确认 / 一键批量确认 / 未收到款退回 / 提醒付款（每日一次）
- ✅ 当面支付全链路：选择当面支付 → 提货时「当面已收款」；unpaid 者提货时可「提货时已收现金」
- ✅ 截单时未确认付款弹窗提示，不强制阻断
- ✅ 团长可编辑「拼单中」的拼单全部信息（含改价、改份数、换收款码），保存后参与者应付金额自动重算；已截单不可编辑
- ✅ 团长可移除参与者，份额即时释放；已付款者移除前提示线下退款
- ✅ 取消拼单通知全部参与者，已付款者看到"联系发起人退款"提示
- ✅ 参与者确认提货，团长端提货状态同步；全员提货自动完成

## 多人联调小技巧

- 开发者工具「多账号调试」或「预览」到手机，用两个微信号分别当团长 / 邻居。
- 分享卡片在真实微信群中体验最完整；工具内可用「转发」模拟。
- 需要秒级验证自动截单时，把截单时间设为 1-2 分钟后，等待定时器（5 分钟一轮）或直接手动截单。

## 已知边界

- 「发起人实时显示」采用进入页面 / 下拉刷新 / 操作后刷新的准实时策略，未引入 websocket watch。
- 参与后暂不支持自行退出或改份额（如需要可在「拼单中」阶段加一个 leaveGroupBuy action，事务内回减 `sold_shares`）。
- 订阅消息依赖用户授权与模板配置，未配置时一切功能照常，只是不推送。
